Notes on that probe:
- **No buffering:** the upstream was gated behind an `asyncio.Event` that is never set until
  after the first chunk is read. The first proxy chunk still arrived within 2 s while the
  upstream log showed only one chunk produced — a buffering implementation would have hung.
- **Abort:** `aclose()` mid-stream flips the upstream stream's `closed` flag to `True`.
- **Sockets:** the only bind is `('127.0.0.1', 0)` — the asyncio event loop's self-pipe on
  Windows (port 0 = ephemeral, loop-owned), not the gateway binding a port.

## 8. Two caveats the Builder flagged (verify or refute)

1. `host`, `content-length` and `connection` are always (re)generated by httpx on the outgoing
   request, so a literal "header absent" assertion is unobservable for those three. Test 3
   instead spoofs distinctive inbound values and asserts the captured upstream request carries
   the regenerated correct values. The other eight hop-by-hop headers are asserted absent.
2. `httpx.ASGITransport` coalesces body parts (`ASGIResponseStream` joins them), so per-chunk
   boundaries are not observable through the ASGI client. Test 4 therefore proves per-chunk,
   in-order relay at the engine boundary and byte-exact fidelity end-to-end.

Judge whether these are legitimate constraints or convenient excuses.
